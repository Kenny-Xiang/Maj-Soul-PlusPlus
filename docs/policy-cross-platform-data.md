## 天凤三麻原始语料验收

| 数据库 | 字节数 | 三麻原始记录 | 完整三麻南场 |

| 合计 | 3,382,693,888 | 99,727 | 99,074 |

全量三麻原始记录逐个解压、解析 XML，并核对 `GO` 三麻标记、三个真实玩家、起始段位与 Rating、各小局结果、最终 `owari`。首版检查曾误判一场终局之后带 `BYE` 的记录，已修正为核对最后一个牌局动作，允许终局后的连接状态事件；该修正不改变已固定的 50,000 场清单。数据库自身的 `was_error=0` 不能代替这项核验。完整三麻包含少量东场，上表最终候选只采用南场。两个库之间未发现重复牌谱 ID 或重复 XML 内容。

候选集合按时间／ID 固定选取 2016 年 47,491 场与 2017 年 2,509 场，恰好 50,000 场、452,990 小局。三席起始 `UN.dan` 均为 16–20，即七段、八段、九段、十段、天凤位，映射与 [kobalab 原始转换说明](https://blog.kobalab.net/entry/20170720/1500479235)一致；所选出场玩家 Rating 为 2001.71–2493.92。包含 47 场快卓（`GO=249`），另 49,953 场为 `GO=185`，原值保留。这个集合偏重 2016 年，截止 2017-01-18，尚未做训练／验证／测试划分，也不能代表近期雀魂的玩家分布。

## 50,000 场三麻 MJAI 转换结果

所选 50,000 场全部转换成功，失败 0 场，逐场通过项目现有 `validate_game(..., players=3)` 结构检查。共 33,864,741 条事件，压缩 MJAI 文件合计 381,888,769 字节，批量运行耗时 242.33 秒。

| 动作事件 | 数量 |
| --- | ---: |
| 出牌 | 14,539,061 |
| 拔北 | 1,155,701 |
| 碰 | 426,522 |
| 暗杠 | 30,910 |
| 加杠 | 17,616 |
| 大明杠 | 2,597 |
| 立直宣言 | 337,178 |
| 和牌 | 384,733 |

事件数不是可用训练样本数，尤其不能把每次弃牌都直接视为含全部正确合法候选的样本。转换器按 XML 原始顺序生成三席 MJAI，使用本项目的 `kita` 拔北方言，`_tenhou` 扩展保存原始事件、物理牌编号以及拔北手切／摸切证据。独立核对每次消耗牌确实在该玩家手中、碰杠来源对应、没有重复摸入物理牌，源分数在小局之间及最后 `owari` 前后衔接。

这些检查不独立计算符番点数，也不证明全部动作合法；完整摸打轮次、振听、抢杠／抢北触发、其他玩家放弃鸣牌的状态仍需训练样本提取器验证。初始 10 场通过 RiichiEnv 0.4.10 接收并匹配 2,773 次朴素动作检查；另有 1,000 场转换覆盖和 5 类明确拒绝的破坏性负例。这些有限的引擎检查未被扩大宣称为 50,000 场完整合法重放。

交付位置均在 `research/cross-platform/`：

- `tenhou-sanma-mjai/data/games/`：50,000 份 `.mjai.json.zst`。
- `tenhou-sanma-mjai/manifest.jsonl`：逐场源 XML 哈希、输出哈希、事件与结构审计。SHA256 为 `b972b1a5911aa0a5924518f87b7d479c9a58c9271b099ad46da8c87b07336f7f`。
- `tenhou-sanma-mjai/report.json`：完整批量结果，明确 `legalActionReplay=false`、`trainingEligibleGames=0`。
- `strict_tenhou_xml.py`：研究用直接 XML 转换器，SHA256 为 `4defd2e1a251963ac2b5d5ff51da2f05d7ae6a4d6138547d3d76947e8cf18465`。
- `audit_tenhou_candidates.py`、`convert_selected_tenhou.py`：原始候选筛选和批量转换复现脚本；后者要求新输出目录，避免覆盖已有结果。
- `tenhou-xml-conversion-findings.json`、`tenhou-xml-pilot/`：编码依据、试转、负例及有限引擎检查。

脚本全部从只读本地 SQLite 取数据，无游戏网络操作。转换语料仍独立于训练集合，没有修改模型或在线执行开关。

三份记录均有全部起手、摸打、鸣牌、拔北和终局结果。28/28 个小局分数衔接通过，3/3 场最终分数匹配官方索引，正确处理了 1 次立直宣言牌放铳而立直未成立的情况。共观察到 64 次拔北、30 次碰、1 次大明杠和 1 次加杠，没有吃。此验证是结构和分数连续性检查，尚不是逐事件合法动作重放。

转换不能直接套用现成脚本：

- 这些三麻数据仍使用四席局号 `0,1,2,4,5,6`，南场不能用 `round // 3` 解码。
- CityLogs 用 `f44` 表示拔北；当前项目的 RiichiEnv 方言需要 `kita`。当前安装的 RiichiEnv 0.4.10 实测会静默忽略另一常见方言 `nukidora`，因此必须明确转换。
- 样本出现点数字符串与实际分数增减不一致：庄家 50 符 2 番标成 `1100-1000点`，实际两名付款者各扣 1600。不能使用显示字符串生成点数训练标签。

细节、原始样本哈希、公开请求参数保存在 `research/alternative-platforms.json` 和 `research/riichicity-sanma-sample-validation.json`。这里的 `research/` 均相对于 `.local/high-rank-50k/`。

## 与雀魂的规则兼容性

天凤和雀魂可以共享大部分基础局面和动作学习素材，但不能声明规则完全相同。依据 [天凤官方手册](https://tenhou.net/man/)、[雀魂段位规则](https://mahjongsoul.com/news/46)及当前官方役种配置，已确认：

| 项目 | 天凤 | 雀魂 | 对本次动作模仿学习的影响 |
| --- | --- | --- | --- |
| 四麻起始／返还点 | 25000／30000 | 25000／25000 | 可能影响玩家偏好；最终收益不作为训练标签 |
| 三麻起始／返还点 | 35000／40000 | 35000／35000 | 同上；当前点数仍属于可见局面 |
| 四麻三家荣和 | 途中流局 | 三家均和 | 保留源实录终局，执行时服从雀魂当前操作窗口 |
| 国士抢暗杠 | 不允许 | 允许 | 合法动作集合不同，不能把源平台无此选项误标为主动跳过 |
| 特定双倍役满 | 单役满 | 双倍役满 | 可能影响动作偏好，不要求生成或重算价值标签 |
| 复合役满包牌 | 对复合役满承担责任 | 只承担相关责任役满部分 | 保留源实录当时点数；不训练收益预测 |

三麻核心玩法接近：去掉二至八万、不能吃、可拔北；雀魂官方明确采用自摸损。仍需覆盖连续杠、翻宝牌时点、抢北、一发取消、立直后拔北等边界。规则证据及引擎预设对照保存在 `research/cross-platform-rules.json`；官方配置核验在 `research/mjsoul-yakuman-config-evidence.json`。

一番街目前仅由样本验证了 35000 起始点、拔北、若干自摸损和荣和每本场增加 200 点；尚未取得完整官方三麻规则并覆盖所有边界，因此只列为转换研究候选。

[SEGA MJ 三麻](https://sega-mj.com/players/gameguide/manual/rule/rule_b/)和 [Maru-Jan 三麻](https://maru-jan.com/guide/table/game_3ma_rule.html)不优先采用。前者北为共同役牌、自摸付款有补偿等，后者北为常驻宝牌，均不能直接当作雀魂的拔北三麻。

## 如何用于模型

用户明确采用监督动作模仿学习：输入决策时的可见牌局状态，标签为高段位玩家实际选择的动作，输出当前合法动作集合上的选择。训练损失为专家动作的交叉熵 `-log P(action_label | visible_state, legal_actions)`，不训练收益、最终顺位或价值预测，也不增加强化学习目标。

输入可以保留本人手牌、各家已公开的牌河和副露、立直状态、宝牌指示牌、场风／局数、本场／供托、当前点数及剩余牌数。当前点数是决策条件，不是收益监督目标。完整牌谱虽含所有人的起手与未来事件，样本必须按决策时点和玩家视角生成；对手暗手、未来摸牌、未来里宝牌、终局分数和后续动作不能进入特征。

动作标签保留出牌种类及红牌、立直、碰杠消耗牌、来源席位、拔北、和牌及跳过等参数。只有确实存在选择的操作窗口才能产生跳过标签；源平台没有某个合法动作，不能当成玩家主动拒绝。拔北和手切／摸切从 XML 物理牌编号还原，雀魂执行参数再由当前操作窗口匹配。

真实记录包含 `BYE` 掉线事件，掉线期间的自动动作不能一律标作高段位玩家主动选择。当前 MJAI 转换跳过连接状态事件，完整 XML 仍在来源库中；正式样本提取需要从原谱恢复这类区间并过滤。现在的 MJAI 事件统计没有扣除这些窗口。

现有代码已采用上述目标：`src/policy_training.py` 用真实动作在合法候选中的索引作 target，并计算交叉熵；`src/policy_corpus_training.py` 的流式训练亦如此。三／四人特征、候选评分网络和训练入口可复用。当前三麻不足集中在 MJAI 局面投影与决策窗口提取的四人假设和缺少拔北处理，收益重算不是实现这些功能的前置条件。

平台、玩法、年代、原始局号、段位和规则信息保留为数据来源与验证元数据。同一场完整对局及其所有小局、座位必须进入同一个训练／验证／测试集合。完整原谱、MJAI 转换通过、状态重放通过和训练可用分别计数。

跨平台的最终收益差异不作为本次动作转换的阻塞条件。保留源实录局面和专家实际动作，重点核验可见信息边界、动作标签与合法候选是否对齐；规则差异影响合法动作的窗口应过滤或单独处理。支付规则不同仍可能影响玩家选择，应在雀魂留出集上检验迁移效果，不能仅凭训练拟合率宣称棋力。部署另外沿用真实协议的离线动作回放验收。

[天凤官方日志页](https://tenhou.net/sc/raw/)明确限制竞争产品及无需天凤对局的服务用途，一般麻将应用要求联系原站。公开镜像和第三方许可证标签不代表已取得用于雀魂推荐模型的许可。本次保留为来源研究和转换核验材料，没有将天凤数据加入训练或替换当前模型。CityLogs 文档也未说明批量使用速率和原始数据许可。

现有四麻数据、试训结果和游戏动作对接状态见 [policy-50k.md](policy-50k.md)。本次未修改主仓库、原模型工作目录或桌面 App，也未进行在线自动对局。
