## 后续 500 场三麻监督样本提取

`src/policy_mjai.py`、`src/policy_mjai_state.py` 和 `scripts/policy_convert_mjai.py` 现已支持带原 XML 证据的天凤三麻。新的入口逐场复核压缩 MJAI 与 XML 哈希、三席 `GO`／`UN` 头及七段至天凤位段位；元数据明示 `sourcePlatform=tenhou`、`ruleEngineRules=tenhou`，不冒充雀魂房间。引擎采用天凤规则重建当时合法候选，网络训练目标仍只是源高段位玩家的实际动作。

本轮排除开发 XML 转换器时使用的前 1,000 场，从余下 49,000 场按固定哈希顺序提取 500 场；18 场因含 `BYE` 被整场剔除后补足目标。该保守策略也剔除终局后出现 `BYE` 的牌谱，不尝试猜测断线期间哪些动作出自人类。来源选择记录为 `.local/high-rank-50k/research/cross-platform/pilot-source-selection.json`。

转换得到 **161,180 条样本**：出牌 127,265、拔北 11,518、碰 4,218、暗杠 273、大明杠 21、加杠 168、立直 3,166、自摸 1,816、荣和 1,689、九种九牌流局 125、跳过 10,921。其中 150,259 条是直接动作标签，10,921 条跳过仅从下家正常摸牌明确关闭响应窗口推断。所有保留标签均匹配转换前冻结的合法候选，没有根据标签补造候选。

三麻局面按三个真实座位投影，开局首摸后剩余牌墙为 54，拔北数量为公开信息。拔北手切／摸切使用原 XML 的物理牌证据，无法确定则排除当前标签。模型只获得行动者自己的手牌和摸牌、公开局面与当前候选，不获得暗手、未来摸牌或终局结果。`sourcePlatform`、`ruleEngineRules`、原始段位、年代和哈希仅用于来源审计，不进入神经网络特征；经证据确定的场长属于当前局面。

已修补 RiichiEnv 0.4.10 MJAI 重放遗漏的拔北补牌岭上标志：副露无役手只靠岭上构成和牌时，自摸应进入候选；后续普通摸牌不得沿用该标志。新增回归同时验证这两种情况。无役形听漏和仍依据天凤官方规则追踪同巡振听，不因采用纯动作监督而省略合法性状态。

目前保留杠动作本身，排除任一杠后到本小局结束的窗口；500 场触发 495 次此类杠事件。对潜在抢北响应尚未验收的窗口，若他家形听 North，则排除拔北后的小局后续窗口，触发 3 次。另有 137 个竞争响应被遮蔽。这里隐藏听牌只影响源规则重建和保守过滤，不写入特征；保留样本集合仍可能随过滤条件变化。事件次数不等于被排除决策的精确数量。

完整命令及新增回归见 [三麻转换入口](policy-mjai.md#天凤三麻入口与-500-场样本验收)。本轮报告为 `.local/high-rank-50k/three-player-pilot-training/report.json`，压缩分片共 11,342,640 字节，转换器签名为 `96872ac64e57897511a367b3d25e9f26958a738cbe0ab9de61b6cf8feb6e4f42`。这份报告证明 500 场的有限样本提取，不能推及 50,000 场全部可直接训练，也不证明三麻模型棋力；模型训练和实时双槽验收另见 [策略模型设计](policy-model.md)。

## 与雀魂的规则兼容性

天凤和雀魂可以共享大部分基础局面和动作学习素材，但不能声明规则完全相同。依据 [天凤官方手册](https://tenhou.net/man/)、[雀魂段位规则](https://mahjongsoul.com/news/46)及当前官方役种配置，已确认：

| 项目 | 天凤 | 雀魂 | 对本次动作模仿学习的影响 |
| --- | --- | --- | --- |
| 四麻起始／返还点 | 25000／30000 | 25000／25000 | 可能影响玩家偏好；最终收益不作为训练标签 |
| 三麻起始／返还点 | 35000／40000 | 35000／35000 | 同上；当前点数仍属于可见局面 |
| 四麻三家荣和 | 途中流局 | 三家均和 | 保留源实录终局，执行时服从雀魂当前操作窗口 |
| 国士抢暗杠 | 不允许 | 允许 | 合法动作集合不同，不能把源平台无此选项误标为主动跳过 |
| 特定双倍役满 | 单役满 | 双倍役满 | 可能影响动作偏好，不要求生成或重算价值标签 |
| 复合役满包牌 | 对复合役满承担责任 | 只承担相关责任役满部分 | 保留源实录当时点数；不训练收益预测 |

三麻核心玩法接近：去掉二至八万、不能吃、可拔北；雀魂官方明确采用自摸损。仍需覆盖连续杠、翻宝牌时点、抢北、一发取消、立直后拔北等边界。规则证据及引擎预设对照保存在 `research/cross-platform-rules.json`；官方配置核验在 `research/mjsoul-yakuman-config-evidence.json`。

一番街目前仅由样本验证了 35000 起始点、拔北、若干自摸损和荣和每本场增加 200 点；尚未取得完整官方三麻规则并覆盖所有边界，因此只列为转换研究候选。

[SEGA MJ 三麻](https://sega-mj.com/players/gameguide/manual/rule/rule_b/)和 [Maru-Jan 三麻](https://maru-jan.com/guide/table/game_3ma_rule.html)不优先采用。前者北为共同役牌、自摸付款有补偿等，后者北为常驻宝牌，均不能直接当作雀魂的拔北三麻。

## 如何用于模型

用户明确采用监督动作模仿学习：输入决策时的可见牌局状态，标签为高段位玩家实际选择的动作，输出当前合法动作集合上的选择。训练损失为专家动作的交叉熵 `-log P(action_label | visible_state, legal_actions)`，不训练收益、最终顺位或价值预测，也不增加强化学习目标。

输入可以保留本人手牌、各家已公开的牌河和副露、立直状态、宝牌指示牌、场风／局数、本场／供托、当前点数及剩余牌数。当前点数是决策条件，不是收益监督目标。完整牌谱虽含所有人的起手与未来事件，样本必须按决策时点和玩家视角生成；对手暗手、未来摸牌、未来里宝牌、终局分数和后续动作不能进入特征。

动作标签保留出牌种类及红牌、立直、碰杠消耗牌、来源席位、拔北、和牌及跳过等参数。只有确实存在选择的操作窗口才能产生跳过标签；源平台没有某个合法动作，不能当成玩家主动拒绝。拔北和手切／摸切从 XML 物理牌编号还原，雀魂执行参数再由当前操作窗口匹配。

真实记录包含 `BYE` 掉线事件，掉线期间的自动动作不能一律标作高段位玩家主动选择。原 MJAI 转换跳过连接状态事件，因此新增样本提取器必须回读完整 XML，并保守排除含 `BYE` 的整场。上文 50,000 场 MJAI 事件统计没有扣除这些记录；500 场样本统计已经经过该过滤。

现有代码已采用上述目标：`src/policy_training.py` 用真实动作在合法候选中的索引作 target，并计算交叉熵；`src/policy_corpus_training.py` 的流式训练亦如此。三／四人特征合同、候选评分网络和训练入口复用，但分别训练和加载独立权重。三麻 MJAI 局面投影与拔北标签已在上述 500 场完成有限验收；后续杠与抢北边界仍保留过滤。收益重算不是这些功能的前置条件。

平台、玩法、年代、原始局号、段位和规则信息保留为数据来源与验证元数据，不因它们出现在审计记录中就自动作为模型输入。同一场完整对局及其所有小局、座位必须进入同一个训练／验证／测试集合。完整原谱、MJAI 转换通过、状态重放通过和训练可用分别计数。

跨平台的最终收益差异不作为本次动作转换的阻塞条件。保留源实录局面和专家实际动作，重点核验可见信息边界、动作标签与合法候选是否对齐；规则差异影响合法动作的窗口应过滤或单独处理。支付规则不同仍可能影响玩家选择，应在雀魂留出集上检验迁移效果，不能仅凭训练拟合率宣称棋力。部署另外沿用真实协议的离线动作回放验收。

[天凤官方日志页](https://tenhou.net/sc/raw/)明确限制竞争产品及无需天凤对局的服务用途，一般麻将应用要求联系原站。公开镜像和第三方许可证标签不代表已取得用于雀魂推荐模型的许可。后续 500 场用于独立的离线样本与训练管线实验，不构成跨产品部署许可的确认；全量正式使用和部署仍需单独处理来源条件。CityLogs 文档也未说明批量使用速率和原始数据许可。
