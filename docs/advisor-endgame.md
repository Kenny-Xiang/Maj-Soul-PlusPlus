# 终盘排名偏好与输入边界

排名偏好只在调用方提供 `round.isFinal: true` 时启用。这个字段声明当前为**计划末局**，不是“本局无论何种结局都一定结束”；连庄、延长及自定义结束规则仍未建模。标记必须与该局的 `round.chang`、`round.ju`、`round.ben` 一起由可信赛制信息提供，字符串 `"true"` 和整数 `1` 均不启用。

当前 `core.cjs` 只解析场风、庄家编号、本场数、人数和点数，没有解析东风／半庄／自定义局数。它在和牌或流局后才收到是否整场结束的信息。因此，**桌面实时采集尚不会产生 `round.isFinal`，默认不会启用下面的终盘调整**。不能把南四、南三、西场或高本场数直接认作末局。输入适配器和离线评估可以在掌握实际赛制时提供该标记；单纯写入标记不等于完成了协议接入。

新增 `_rank_context` 输出的 `rankRange` 使用分数区间表达名次，例如并列第三为 `[3, 4]`。本实现不把当前庄位或座位号当作初始座次，不猜同分结算顺序，也不臆造段位积分、顺位马、返还点或剩余局数。输出的 `source` 为 `explicit-round-marker`、`unknown-match-length` 或 `incomplete-scores`，用于核查调整的输入依据。

原点数风险权重保持：基础 1.15、领先至少 8000 加 0.30、严格末位减 0.15、本人不足 8000 加 0.20。在有明确末局标记且本人分数不与他人相同的情况下，追加下表的有限偏好：

| 条件 | `objective` | 风险权重增量 | 目的 |
|---|---|---:|---|
| 独占第一 | `protect-first` | +0.25 | 保护领先，包含不足 8000 的领先 |
| 倒数第二且领先末位不超过 8000 | `avoid-last` | +0.20 | 四麻避四／三麻避三 |
| 独占末位，且不是庄家 | `escape-last` | −0.15 | 接受更多风险争取逆转 |
| 独占末位，且是庄家 | `escape-last` | −0.075 | 保留连庄可能，逆转偏好减半 |
| 其余情况，或本人参与同分 | `points` | 0 | 延用点数风险偏好 |

这些增量和 8000 点的缓冲界限是**人工偏好，未经牌谱校准**。增量作用于模型已有的放铳损失，不改听牌率、条件命中率或命中后的付款；不能把它们解释为名次概率或真实结算价值。模型还未逐一模拟“向某位对手放铳／自摸后是否换位”，也未计算连庄的未来收益，所以保位和逆转只是有明确前提的有限调整。

验证命令：

```sh
PYTHONPATH=src PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m unittest discover -s tests -p test_advisor_endgame.py
```

测试覆盖四麻与三麻、末位庄家、8000 点边界、同分区间、未知赛制不推断末局、严格布尔标记、非本人初始座位以及输入不变。前三项行为测试在修改权重前失败，证明原模型未使用显式末局信息；测试通过只证明规则按约定执行，不证明提高实战顺位或棋力。
