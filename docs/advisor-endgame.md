# 排位偏好与输入边界

目标是让攻守决策考虑上分收益。v10 在已识别的普通段位场自动使用官方顺位奖励与扣分，配合当前点差、剩余计划局数计算有界风险偏好。它替代原来的“领先 8000／末位／自身不足 8000”固定加减项；未识别赛制保持旧行为。该调整是未经实战校准的启发式，不是完整的最终段位分期望。

## 自动读取

采集器关联 `.lq.FastTest.authGame` 请求和响应，用请求中的本人账号匹配响应 `seat_list` 与 `players`。账号仅在请求关联中短暂使用，不进入 `state` 或输出日志。四麻读取 `level`，三麻读取 `level3`；不能将四麻段位用于三麻。

`state.match` 包括 `source: "auth-game"`、`category: 2`、`modeId`、`room`、`levelId`、按座位排列的 `levelIds`、`playerCount`、`roundCount`。这里 `roundCount` 是预定风数：东风 1、半庄 2，不是小局数。模式编号、人数、风数、房间和本人段位必须与已核对的官方表相容。未知模式、友人／比赛／活动场、身份或人数冲突、旧魂天及未支持等级均不启用新的段位偏好。

认证成功后保留比赛信息跨小局和恢复使用；新认证、新连接、整场结束、连接关闭及解析失败会清除相应信息，避免把上一场规则带到下一场。恢复快照仍遵守原来的完整性限制，取得段位信息不会把不完整手牌变成可行动状态。

已确认赛制时，`round.isFinal` 表示预定末局或延长局，`round.isExtension` 单独标识延长。二者都不能证明这手一定结束整场。未知赛制不会只凭南四或南三生成标记。若赛制已确认但具体段位结算尚不支持，仍可按该可信末局标记使用旧的通用终盘偏好。

## 有界攻守偏好

普通段位场给定最终位次的收益是素点项加顺位固定部分；魂天只按位次获得魂珠。配置与结算边界见[官方规则记录](rank-point-rules.md)。策略用未取整的素点项来保持平滑。

1. 计算剩余计划小局数 `R = max(0, 人数 × 预定风数 − (场风 × 人数 + 庄位) − 1)`。不把未知未来连庄当作已知剩余局数。
2. 对每名对手，用当前点差与 `4000 × sqrt(R + 1)` 的尺度做 sigmoid 平滑，再卷积为各位次的插值权重。它们只是平滑奖励函数的工具，**不是实证名次概率**。同分不猜最终结算顺序，仍报告名次区间。
3. 势函数为 `本人分数 / 1000 + Σ(平滑位次权重 × 官方顺位固定部分)`；魂天不加素点项。
4. 分别模拟向每位对手支付 4000 点及从每位对手获得 4000 点，计算平均势函数损失 `L` 与收益 `G`。这些是对称参考转移，不是对未来荣和对象或手牌打点的预测。
5. 放铳风险权重为 `clamp(1.15 × L / G, 0.75, 1.75)`。纯位次模式分差极大、势函数数值饱和时退回 1.15。

4000 点探针、平滑尺度、1.15 基础权重及上下限都是人工参数，尚未用牌谱或自我对弈校准。既有和牌收入、他家自摸、包牌、流局与动作代价账本保持点数单位。`score` 不应读成预计段位积分。

该权重贯穿当前攻守、前瞻续打、鸣牌后弃牌及补牌分支。以段位信息、分数和对局阶段为键缓存纯计算；手牌变化不影响同一分数局面的偏好。完整诊断输出在 `rankContext`，含官方规则版本、奖励向量、名次区间、剩余计划局数、探针损益、平滑尺度和截断前后权重。

四麻玉之间半庄、雀豪一，三位点数 `[20000,33000,31000,16000]` 在计划末局时，风险权重约 1.423；互换本人和四位的点数后约 0.750。前一局面换雀圣三后约 1.547。相同的本局进攻与弃和收支可因此作出不同选择，体现避四与脱四的不对称，而非固定全场更保守。

## 已知局限

仍没有逐终局追踪所有人的分数向量。因此向末位放铳与向一位放铳的区别、末位从别人身上和牌挤低本人顺位、终盘小和仍不能脱四而大和可以、连庄未来价值、飞人导致提前结束及升降段后的余额重置，均未完整建模。极深末位分差远超参考转移时，权重会回到接近点数目标，不能代替绝境追求大牌的完整策略。

保位不等于所有牌都弃和，追分也不强制押牌：合法役、实际手牌质量、和率与风险仍参与原有完整候选比较。回归测试只证明这些规则与偏好按定义工作，不证明实战上分率改善。

## 未识别赛制的旧行为

无可用排位配置时，基础风险权重 1.15，领先至少 8000 加 0.30、严格末位减 0.15、本人不足 8000 加 0.20。仅调用方明确提供严格布尔 `round.isFinal: true` 时再使用旧的末局偏好：独占第一加 0.25；倒数第二领先末位不超过 8000 加 0.20；独占末位非庄减 0.15、庄家减 0.075。本人同分不追加这些末局项。

## 验证

`tests/test.cjs` 验证真实协议字段与合成认证／恢复帧的关联及生命周期；`tests/test_advisor_rank_rules.py` 验证规则表和已知位次结算；`tests/test_advisor_rank_policy.py` 验证方向性决策、三麻、同分、未知回退、点数账本、连续性和输入不变。原有 `test_advisor_endgame.py` 保留旧输入兼容测试。Native WebKit 与真实登录对局另需现场验证，合成帧测试不能替代这一步。

2026-10-06 验证：390 项原有及首轮新增 Python 回归通过，随后新增的 3 项缓存／三麻／导出回归分别通过；最终非 UI Python 测试总数 393。Node 采集与浮层 45 项通过。全量 Python discover 同时导入的 `test_native.py` 和 `test_overlay.py` 因沙箱 WebKit 服务不可用而失败，后者返回 `WKErrorDomain Code=5`；两项原生 UI 检查未通过，未计入上述 393 项。

14 个公开合成排位局面的[前后比较](benchmarks/advisor-rank-policy-20261006.json)各预热一轮、测量三轮，对照 `0d4ae9a`，基线完整排序、当前使用实时三候选精确前缀。基线中位数／P95／最长为 1008.0／1699.0／1737.6 ms；当前为 1023.5／1685.0／1806.6 ms，两边预热和正式测量均无超时，重复输出一致。两例末局三位的推荐从 6m 改为更安全的 3p；当前仍可能选择名为 attack 的保留进攻路线，不能把更安全的弃牌误称为已完全弃和。样本是现有公开手牌叠加合成点数和段位，用于验证策略方向与预算，不是实战胜率测量。
