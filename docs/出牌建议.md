# 实时出牌建议

功能使用当前窗口收到的本人手牌和公开局面，评估所有已确认合法的弃牌，实时显示综合评分最高的一张。适用普通雀魂三人／四人立直麻将；不会读取对手暗手，也不会自动出牌、立直、鸣牌或和牌。

## 怎么读面板

| 指标 | 含义 |
| --- | --- |
| 推荐牌 | 当前模型评分最高的合法弃牌；赤五与普通五分别比较 |
| 向听 | 弃牌后的最小向听数，同时考虑普通形、门清七对子和国士；0 表示结构听牌，不等于有役 |
| 进张 | 能降低向听的牌在未见牌中的总枚数；扣除本人手牌、宝牌指示、牌河、副露和拔北，被鸣弃牌只计一次 |
| 后续胡牌率（估计） | 有限剩余巡数下，按进张推进及他家提前结束牌局的简化模型估计；未经实战校准 |
| 胡牌得点（估计） | 和牌时的条件平均得点。听牌时逐张检查役种、番符及自摸／荣和；未听牌时按当前牌型估值 |
| 本次放铳率（估计） | 现在打出这张牌，被至少一名对手荣和的估计概率；不是整局放铳概率 |
| 放铳输点（估计） | 本次弃牌发生放铳时的条件平均损失，包含模型中的多人荣和可能 |
| 本次预期损失（估计） | 各对手放铳概率乘其估计得点之和，已经包含概率权重 |
| 攻守评分 | 预计和牌收益减去风险加权的当次放铳损失，再加入效率和临近流局的听牌价值；不是严格的整局期望点数 |

未见牌还包括对手手牌及王牌，无法直接解释为剩余牌山。不要将估计和牌率与当次放铳率相加解释成完整胜负分布，未建模的结局还包括他家自摸、他家互相放铳和流局。

## 计算方式

1. 校验牌局阶段、本人座位、完整性、牌数以及服务端实际操作窗口。已有自摸／荣和操作时显示可和牌提示；立直后仅保留摸切；吃碰后的食替黑名单按普通五／赤五同族排除。
2. 枚举每种可打出的牌，精确计算向听和有效未见进张。七对子、国士仅在无副露面子时参与比较，暗杠也不能组成这两种特殊形。
3. 听牌候选枚举完成形待牌，检查有役、整个听口的舍牌振听及服务端振听状态。宝牌、赤牌及拔北不独立构成起和役。打点使用庄闲、自风／场风、本场和已知宝牌；三麻处理万子移除、1万指示9万、拔北以及自摸损。
4. 对每名对手估计听牌概率和打点。立直视为已听牌，副露和巡目增加威胁；现物、立直后通过的牌、筋和可见牌壁改变当次弃牌风险。筋和牌壁不会被当成普遍的绝对安全依据。
5. 用有限状态推进模型估计未来成牌机会；对评分领先的一向听候选执行有界下一步等待质量检查。牌山越短，追进张的机会越少，结构听牌的流局价值越高。分数领先较多时适当提高防守权重，落后时适当降低。

规则计算依赖固定版本 [MahjongRepository/mahjong 2.0.0](https://github.com/MahjongRepository/mahjong)。雀魂与库默认规则不同的三麻结算、宝牌和拔北在项目内适配。规则范围参考本项目的 [雀魂规则参考](雀魂规则_Agent参考.md)，库许可附在 [mahjong-LICENSE.txt](mahjong-LICENSE.txt)。

## 边界

概率模型采用明示的启发式常量，没有经过真人牌谱训练、概率校准或大规模胜率对战验证。推荐是该模型下的最佳候选，不能保证全局最优或长期盈利。未听牌时的打点、后续进张、他家听牌率及他家打点均包含估算。

不会自动假设未来宣布立直，不预测里宝牌和一发；听牌时按普通规则下尚未出现的赤五数量加权，未听牌时不预测未来赤牌收益。没有完整模拟他家摸打、后续吃碰杠、特殊和牌事件、包牌、整场排名或段位积分；只对当前弃牌建模直接放铳损失，未累计未来每一巡的防守成本。和牌收益包含桌上供托，放铳者损失不把已有供托重复计为付款。

未读取房间自定义规则，普通规则假设会随建议返回。友人房自定义规则和活动模式的结果不保证适用。恢复动作与快照的边界仍未验证，因此恢复阶段会显示暂停推荐，直到新的完整开局。

## 刷新和验证

建议计算在独立后台线程进行。新快照覆盖排队的旧快照；后台结果同时受会话／消息编号校验和浏览器动作触发的即时撤销保护。断线、解析异常和结束不会保留旧推荐。

`./scripts/test.sh` 包含状态协议回归、规则牌例、风险与评分回归、后台并发、原生 WebKit 回放及浮层布局检查。原生测试使用本地样本与模拟 WebSocket，不操作真实牌局。`--verify-advisor` 可在打包 App 内验证规则引擎与依赖是否齐全。

结构化运行日志中的 `kind: advice` 记录包含 `adviceKey`、全部候选、逐家风险、模型名称及计算耗时，可以和同一会话的牌局快照对应复查。
