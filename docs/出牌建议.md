# 实时行动建议

功能使用当前窗口收到的本人手牌、公开局面和服务端操作列表，比较己方当前可选动作。适用普通雀魂三人／四人立直麻将；不会读取对手暗手，也不会自动出牌、立直、鸣牌或和牌。

## 动作范围与刷新

覆盖打牌、吃、碰、大明杠、暗杠、加杠、立直、自摸、荣和、拔北、九种九牌流局，以及当前窗口的跳过选择。仅从服务端允许的动作和牌组合中生成可执行建议。即使手牌看起来能杠或能立直，服务端没有给出该操作时也不会自行开放。

- 吃／碰：比较鸣牌与跳过；模拟失去门清、消耗手牌、加入副露后的牌型与打点，并给出符合食替限制的后续弃牌。
- 立直：与普通出牌／默听单独比较，计入 1000 点供托成本、立直或两立直的役、后续不能自由弃和的代价。收回本人刚支付的供托不会被误算为新增收益。已立直后仅有暗杠／拔北的窗口也会比较跳过及随后强制摸切；四麻第四家立直按途中流局处理，三麻三家立直仍可继续。
- 三类杠／拔北：按可见信息扣除已知牌，对未知补牌进行加权评估，并保留抢杠／抢北及新增宝牌的不确定性说明。补牌尚未出现时不会把某一张假想补牌写成确定的下一张弃牌。拔北补牌自摸计岭上开花，抢北不限定国士且不额外给抢杠役；跨家第四杠仅保留补牌和牌及随后弃牌荣和的机会，再按四杠散了处理。
- 自摸／荣和：服务端已给出和牌操作时优先提示和牌，不以估计概率否定已经合法的和牌窗口。
- 九种九牌：服务端允许时提供流局与继续做牌的比较。该窗口统一去除形状奖励，保留继续做牌的同一终局账目，包括他家自摸付款、包牌责任和普通流局收支。不自行宣布四风连打等服务器裁定的流局。
- 非操作时段：手牌变化后仍更新当前向听、有效进张与牌型估值，显示“等待行动”；此时没有可立即执行的弃牌，界面不显示虚构的当次放铳风险。

每次发牌、摸牌、出牌、吃碰杠和拔北后都会重新计算。玩家向游戏提交操作时立即清除旧结果；后续服务端消息决定新的合法窗口。模型比较当前动作，并对有限剩余机会中的摸打、听牌续打与转守建模；不搜索任意长度的完整对局树。

## 怎么读面板

| 指标 | 含义 |
| --- | --- |
| 推荐行动 | 当前模型评分最高的合法动作；注明吃碰用牌及后续弃牌，赤五与普通五分别比较 |
| 当前策略 | 进攻、弃和、立直续打；补牌动作在各实际补牌分支分别决策 |
| 向听 | 弃牌后的最小向听数，同时考虑普通形、门清七对子和国士；0 表示结构听牌，不等于有役 |
| 进张 | 能降低向听的牌在未见牌中的总枚数；扣除本人手牌、宝牌指示、牌河、副露和拔北，被鸣弃牌只计一次 |
| 有效进张／听口明细 | 列出推荐动作后每种进张及未见张数；听牌时区分仅自摸、仅荣和及无役，已见尽的听口保留为 0 张；补牌动作待实际补牌后再确定明细 |
| 后续胡牌率（估计） | 按所选攻守策略直到终局的胡牌概率估计，不是下一次摸牌的胡牌率；弃和路线不计和牌收入 |
| 胡牌得点（估计） | 和牌时的条件平均得点。听牌时逐张检查役种、番符及自摸／荣和；未听牌时按一次摸打后的牌型或具体作役目标估值 |
| 本次／后续弃牌／操作风险（估计） | 普通弃牌显示本次放铳率，吃碰或跳过后的计划弃牌显示后续弃牌风险；补牌动作显示操作风险，包含抢杠／抢北及补牌后弃牌的风险估计；不是整局放铳概率 |
| 放铳输点（估计） | 发生放铳时的条件平均输点；补牌动作包含被抢及补牌后弃牌放铳，标为操作放铳输点 |
| 本次／后续弃牌／操作预期损失（估计） | 当前动作的放铳概率加权损失，范围与对应风险一致，不包含未来全部弃牌、他家自摸或流局收支 |
| 备选对比 | 最多两条，按行动、向听／未见张数、风险估计、打点估计并列展示；只显示引擎已精确排序的候选前缀，未减少引擎比较的候选范围 |

振听、无役等具体约束优先显示，窄窗口也保留关键提醒。缺少手牌、历史不完整、连接中断和动作未核实会显著提示。正常状态的时间戳、更新次数、动作编号、触发事件及入站数量保留在日志，不常驻右侧面板；解析错误非零时仍提示。

右上集中展示概率、条件得点／输点及预期损失，右下展示进张明细与备选对比。纯跳过、等待行动或非操作时段的手牌评估不显示当前动作的风险和损失。攻守评分仍保留在结构化日志。未见牌还包括对手手牌及王牌，无法直接解释为剩余牌山。当次放铳率不是完整终局分布；结构化日志的 `terminalProbabilities` 列出本人和牌、当前及未来放铳合计、他家自摸、他家互相放铳、普通流局及已知途中流局，合计为 1。终局频率仍是未校准估计。

## 计算方式

1. 校验牌局阶段、本人座位、完整性、牌数以及服务端实际操作窗口。已有自摸／荣和操作时显示可和牌提示；解析服务端提供的动作组合，模拟每种动作后的手牌、副露与牌河，避免把被鸣牌重复计数。
2. 枚举每种可打出的牌，精确计算向听和有效未见进张。七对子、国士仅在无副露面子时参与比较，暗杠也不能组成这两种特殊形。
3. 听牌候选枚举完成形待牌，检查有役、整个听口的舍牌振听及服务端振听状态。宝牌、赤牌及拔北不独立构成起和役。打点使用庄闲、自风／场风、本场和已知宝牌；三麻处理万子移除、1万指示9万、拔北以及自摸损。
4. 对每名对手估计听牌概率和打点。立直视为已听牌，副露和巡目增加威胁；现物、立直后通过的牌、筋和可见牌壁改变当次弃牌风险。先排除实体上无法成立的顺子、对子和特殊形；筋和单壁不会被当成普遍的绝对安全依据。
5. 所有普通非听牌候选展开相同的一次实体摸打，真实进张及同向听形状改良都进入后续收益。补牌已展开一次未知摸牌，随后使用相同叶节点。到达听牌后逐张计分；更远普通形仍用阶段近似。副露未知役不再按 0.3 先验领取收入，而是比较具体役牌／对对和目标；目标按真实缺牌推进并按完成牌型计分。普通结构听口可有流局听牌料，但无役不产生和牌收入。分数领先较多时适当提高防守权重，落后时适当降低；终盘额外偏好仅在可信 `round.isFinal: true` 标记下启用，当前实时采集尚无该标记。

剩余机会按当前座位及动作顺序展开：跳过鸣牌后从原弃牌者的下家继续，吃碰后从自己的下家继续；他家已摸牌或吃碰但尚未弃牌时，保留这次不再消耗牌山的弃牌机会。杠／拔北补牌只扣一次剩余牌。听牌模型逐次计算自摸或荣和，并用同一组概率权重累计获点，再求和牌时的条件平均得点；没有剩余可和牌机会时该均值显示为零。未来未知鸣牌改变顺序的情况仍未模拟。

第一张模拟摸牌按公开未见牌无放回计权，不把进张同时算成和牌。未知未来立直和鸣牌不被免费假定。具体作役目标的尾部也按无放回收集缺牌，只估自摸；多个目标选择其一，不相加重叠概率。七对和国士保留各自的实体牌要求。更远普通形的进张、等待宽度和所持宝牌保留仍含粗估。

当前弃和从预计损失最小的合法牌开始。每张原手牌只使用一次；通过立直者的同种牌可以成为后续安全牌，对其他对手仍计风险。摸入已知对所有对手均安全的牌时直接摸切，保留原手库存，不假想未来他家提供现物。防守不计和牌收入；原手已经听牌且一直安全摸切时，才保留该流局分支的听牌料。拆手后不计保听收益，收到新快照再重新比较。

理由会说明相对下一备选的主要优势来自和牌收入、避险、流局收支还是动作代价；估值差小于 100 点时提示小幅领先。这个提示不改变排序，也不把近似分数包装成确定优势。

规则计算依赖固定版本 [MahjongRepository/mahjong 2.0.0](https://github.com/MahjongRepository/mahjong)。雀魂与库默认规则不同的三麻结算、宝牌和拔北在项目内适配。规则范围参考本项目的 [雀魂规则参考](雀魂规则_Agent参考.md)，库许可附在 [mahjong-LICENSE.txt](mahjong-LICENSE.txt)。

## 边界

概率模型采用明示的启发式常量，没有经过真人牌谱训练、概率校准或大规模胜率对战验证。推荐是该模型下的最佳候选，不能保证全局最优或长期盈利。未听牌时的打点、后续进张、他家听牌率及他家打点均包含估算。

仅在当前确有立直操作时比较立直，不自动假设将来一定立直，也不预测里宝牌和一发。听牌与补牌时按普通规则下尚未出现的赤五数量加权。杠后新宝牌、他家的听牌与抢杠情况未知，相关风险仍属估计。没有完整模拟他家摸打、连续多次鸣牌、特殊和牌事件、隐藏役满、整场排名或段位积分。公开可见大三元／大四喜责任和四杠子分别结算，责任不明及包牌本场分摊使用付款下界；不视作完整包牌裁判。普通续打与立直共用有限策略和终局账目，立直没有转守选项。和牌收益包含桌上已有供托，放铳者损失不把它重复计为付款。

未读取房间自定义规则，普通规则假设会随建议返回。友人房自定义规则和活动模式的结果不保证适用。恢复动作与快照的边界仍未验证，因此恢复阶段会显示暂停推荐，直到新的完整开局。

## 刷新和验证

建议计算在独立后台线程进行。新快照覆盖排队的旧快照，并通过协作取消让进行中的旧搜索尽快退出；后台结果同时受会话／消息编号校验和浏览器动作触发的即时撤销保护。完整计算有 2 秒预算，超时返回不可用，不展示只有部分候选得到精算的结果。检查在搜索分支之间及返回前执行，并非实时系统的硬截止。断线、解析异常和结束不会保留旧推荐。

`./scripts/test.sh` 包含状态协议回归、规则牌例、风险与评分回归、后台并发、原生 WebKit 回放及浮层布局检查。原生测试使用本地样本与模拟 WebSocket，不操作真实牌局。`--verify-advisor` 可在打包 App 内验证规则引擎与依赖是否齐全。

固定状态的新旧版本对比、评分分项及中位数／P95／最大耗时报告见 [离线评估说明](advisor-evaluation.md)。基准与回归检查不提供实战胜率或长期收益证明。

结构化运行日志中的 `kind: advice` 记录包含 `adviceKey`、全部候选、逐家风险、模型名称及计算耗时，可以和同一会话的牌局快照对应复查。

实时 `candidates` 的前 `rankedCandidateCount` 项（通常为 3）精确排序，后续候选保留全部评分与账目但按输入顺序排列；不能将尾部位置当作排名。离线调用 `advise(state)` 仍返回完整排序，见[性能与排序契约](advisor-policy.md#性能验证及适用范围)。

每个候选的 `scoreBreakdown` 记录未舍入的和牌收入、当前／未来放铳损失、风险偏好、他家自摸付款、他家互铳包牌付款、普通流局转移、立直供托及动作调整；零项省略，取整差额单列。各项之和等于评分。终局点数互斥结算，概率、远期牌型及风险偏好仍含启发式，因此综合分不等于真实整局期望值。`futureFoldProbability` 仅表示曾经转守的路径质量，不能再加到终局分布中。

有限策略和付款边界见[模型说明](advisor-policy.md)；分层校准的数据契约和真实数据缺口见[校准入口](advisor-calibration.md)；显式末局标记的输入限制见[终盘偏好](advisor-endgame.md)。
