# Maj-Soul++

**双击桌面的 [Maj-Soul++.app](/Users/kenny/Desktop/Maj-Soul++.app) 即可。** 应用打开独立的雀魂游戏窗口，统计显示在窗口上半区的半透明浮层中，不打开终端。

适用环境：**Apple Silicon Mac、macOS 14 或更新版本**。应用包内集成 Python、PyObjC、采集脚本和界面资源；正常使用不需要另装 Python、Node.js 或 Xcode，也不依赖桌面旁边的源码文件夹。

新应用使用独立的网站数据目录，本次迁移后需要在新窗口登录一次；之后可复用仍有效的登录状态，过期后重新登录。关闭主窗口或选择“退出 Maj-Soul++”结束程序。再次打开应用会唤起现有窗口，不另开游戏窗口或日志终端。

**更新与重置规则**

1. 每小局收到开局发牌消息后，立即建立新的手牌、弃牌和副露统计，并刷新一次，无需等待本人摸牌或出牌。
2. 此后每个收到且未重复的场上动作都会刷新，包括所有玩家的摸牌、弃牌、吃碰杠、拔北、和牌和流局。浮层始终显示最新状态，不累积旧面板。
3. 整场结束后自动清空当前手牌、弃牌、副露、分数、宝牌、拔北等统计，更新计数及当前对局接收、错误计数归零，显示“对局已结束，统计已重置 · 等待下一场”。
4. 小局结束时保留最新统计，等下一次发牌建立新基线；整场结束时清空面板。历史本地日志保留。

重复动作和同一小局重复发牌不会重复刷新或回滚统计。恢复响应只显示一次恢复后的当前状态，不逐条重播历史统计；心跳不刷新浮层。

**显示与操作**

浮层使用深色半透明底、固定左右两栏和本人手牌高亮，随窗口大小适配并保持在上半区。左侧显示最新动作、本机座位、剩余牌、局况、手牌、宝牌、分数、各家弃牌与副露、拔北及已知牌计数；右侧显示记录状态、更新时间、更新次数、动作序号、完整性说明、触发事件、消息接收与解析错误计数。鼠标点击穿透到底层页面，保留下半区手牌操作位置。最新动作注明动作方，例如“开局发牌”或“座位2 出牌”。

统计包含本人手牌、本机座位、局况、分数、剩余牌数、宝牌指示牌、各家弃牌与副露、拔北、已知牌计数和完整性说明。断线时标明已有统计可能过时。

采集器在页面加载前自动安装，重新加载时也会自动安装。不需要检查器、粘贴脚本、连接按钮或中转窗口。

**本地数据与完整性**

运行数据统一保存在：

```text
~/Library/Application Support/Maj-Soul++/
```

其中 `logs/` 保存每次运行的文本 `.txt` 和结构化 `.jsonl` 记录；`launcher.log` 保存启动诊断，锁文件用于避免重复启动。应用在后台写入日志，不打印终端统计。日志只记录统计快照和状态，不记录登录 token；显示时间按北京时间。应用包内的历史资料保持只读，新的运行数据不写回应用包。

监听只针对 Maj-Soul++ 打开的独立窗口，不接管原 Safari「雀魂麻將」App 的会话。开局消息可建立本小局完整基线；中途进入对局时，完整性取决于服务端恢复数据。没有可信基线时明确标注缺失；漏步、未知动作或数据不一致会取消完整标记。自动更新不能保证补回监听前的全部历史。

对手未公开手牌不会由程序推测。已知牌计数合并赤五与普通五；被鸣走的弃牌保留历史标记，但不与副露重复计数。这些计数不等于剩余牌山的精确分布。恢复快照的特殊弃牌编码及恢复边界仍待更多真实样本核对。

**连接方式与证书**

游戏页面通过系统 WebKit 原生消息接口把数据送入应用内的 Python，再更新浮层和本地日志。没有本机 HTTP/HTTPS 接收端，无需证书信任或外部中转。

此前本项目的自签名证书、私钥及钥匙串信任已经撤回，历史记录见 [证书回退记录.json](./verification/证书回退记录.json)。应用包的临时代码签名用于本机运行，不安装证书或修改钥匙串信任。

**应用包结构与维护**

桌面现用的 `Maj-Soul++.app` 保持原样。源码工程另保存在桌面的 `Maj-Soul++/`，开发、测试和构建步骤见工程根目录的 [README](../README.md)。工程将当前源码放在 `src/`、测试及样本放在 `tests/`、旧中转方案放在 `legacy/`，研究资料和历史验证证据分别放在 `docs/` 与 `docs/verification/`。

从工程运行 `./scripts/build.sh`，产物为 `dist/Maj-Soul++.app`，不会覆盖桌面现用 App。在 Finder 中右键新构建的 App，选择“显示包内容”，可查看：

```text
Contents/
  MacOS/                  应用入口
  Frameworks/             随包 Python 运行时与二进制依赖
  Resources/
    docs/使用说明.md      本说明及研究资料
    docs/verification/    历史验证证据
    source/               完整源码工程，含 src、tests、legacy 等目录
```

当前应用名、窗口与菜单统一为 Maj-Soul++。网站本身仍称雀魂；历史证据中的原始名称保留，不能据此判断当前启动方式。

构建采用 **PyInstaller 6 的 `onedir`、`windowed` 模式**，将独立 Python 及依赖封装为一个 macOS `.app`。`windowed` 在 macOS 上生成无控制台的应用包；`onedir` 将运行所需文件收集在包内。构建配置负责收集采集脚本、浮层、源码和文档。参见 [PyInstaller 官方使用文档](https://pyinstaller.org/en/stable/usage.html)。

维护时直接使用桌面的源码工程，按 [README](../README.md) 准备 Python 3.12 环境，再执行测试和构建脚本。构建所需依赖记录在根目录的 `requirements-build.txt` 中；运行新 App 不依赖工程目录或构建环境。不要直接修改已签名应用内的文件。普通使用无需执行构建或测试命令。

旧完整桌面备份仍保存在原已安装 App 的 `Contents/Resources/archive/桌面原文件备份.tar.gz`，可用于恢复旧文件。该压缩备份没有复制到源码工程，新构建的 App 也不再包含它；源码中的 `legacy/` 单独保留了旧方案代码。
