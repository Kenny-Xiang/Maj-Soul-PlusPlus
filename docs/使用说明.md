# Maj-Soul++ 使用说明

双击 `Maj-Soul++.app` 即可打开独立的雀魂游戏窗口。统计显示在窗口上半区的半透明浮层中，应用不打开终端。

适用环境为 **Apple Silicon Mac、macOS 14 或更新版本**。应用包内集成 Python、PyObjC、采集脚本和界面资源；正常使用不需要另装 Python、Node.js 或 Xcode，也不依赖旁边的源码文件夹。

## 启动与退出

首次使用请在独立窗口登录，之后可复用仍有效的登录状态，过期后重新登录。应用使用自己的 WebKit 网站数据目录，不接管 Safari 或其他雀魂 App 的登录会话。

关闭主窗口或选择“退出 Maj-Soul++”结束程序。再次打开应用会唤起现有窗口，不另开游戏窗口。采集器在页面加载前自动安装，无需手动配置。

## 更新与重置

1. 每小局收到开局发牌消息后，立即建立新的手牌、弃牌和副露统计，并刷新一次。
2. 此后每个收到且未重复的场上动作都会刷新，包括所有玩家的摸牌、弃牌、吃碰杠、拔北、和牌和流局。浮层始终显示最新状态。
3. 小局结束时保留最新统计，等下一次发牌建立新基线。
4. 整场结束后清空当前手牌、弃牌、副露、分数、宝牌、拔北等统计，更新计数及当前对局接收、错误计数归零，显示“对局已结束，统计已重置 · 等待下一场”。历史本地日志保留。

重复动作和同一小局重复发牌不会重复刷新或回滚统计。恢复响应只显示一次恢复后的当前状态，不逐条重播历史统计；心跳不刷新浮层。

## 浮层内容

浮层使用深色半透明底、左右两栏和本人手牌高亮，随窗口大小适配并保持在上半区。顶部的自动打牌开关、三麻／四麻及东风／南风按钮可点击；其余内容继续让鼠标点击穿透到底层页面，保留下半区手牌操作位置。按钮支持 Tab 聚焦、空格或 Enter 操作。

- 左侧显示最新动作、本机座位、剩余牌、局况、手牌、宝牌、分数、各家弃牌与副露、拔北及已知牌计数。
- 右侧显示记录状态、更新时间、更新次数、动作序号、完整性说明、触发事件、消息接收与解析错误计数。

最新动作注明动作方，例如“开局发牌”或“座位2 出牌”。断线时会标明已有统计可能过时。

其他玩家立直成立后，在玩家名称后显示“（已立直）”；普通立直和两立直均支持。标记以服务器的立直成立消息为准，宣言失败或宣言牌被荣和时不提前标记。标记在本小局内保留，下一小局发牌或整场结束时清除。中途接入时，只标记已收到成立确认或从恢复动作中重建的立直；仅有待核对快照时，未确认的立直状态保留为未知。

## 自动打牌

每次启动时自动打牌默认关闭，对局模式默认四麻，场次默认东风。先在游戏窗口登录，再在浮层顶部选择“四麻”或“三麻”以及“东风”或“南风”，打开“自动打牌”开关。若已有有效登录，启动时也可以提前开启；客户端完成加载和认证后会继续。手动登录、验证码和账号提示仍由你处理，点击游戏区域会暂停自动打牌，处理完后需重新开启。

当前实现使用 Unity 客户端的已登录连接，读取账号信息并按所选模式的独立段位、东风或南风对应的金币门槛选择最高符合条件的普通段位房间；实时开放和其他业务资格仍由服务器决定，服务器拒绝时会明确暂停。没有符合条件的房间时不会随意排队。人数与场次设置用于下一次匹配，切换时不取消已经加入的队列，正在进行的牌局按其实际规则处理。南风使用其自身的金币门槛，例如金之间东风需 5,000、南风需 7,000。

金币不足时会显示读到的余额和当前段位的最低入场要求；段位没有读取成功时会单独提示。关闭后重新开启会重新读取本人账号信息，个人资料查询不会覆盖匹配所需的金币余额。

自动操作只支持已确认的普通段位场三麻／四麻；友人房、活动、观战和牌谱不执行。支持弃牌、立直、吃碰杠、拔北、九种九牌、跳过、自摸及荣和。每次提交前重新核对当前手牌、局数、座位、服务端合法操作和组合，吃碰后重新计算弃牌。每个操作只发送一次，并等待服务器回执及对应的牌局动作；异常、旧建议或未确认结果不会触发盲目重试。

每次行动从服务端操作窗口出现时开始计时，建议计算与等待同时进行。强制摸切、明确和牌和优势明显的选择通常较快；备选之间存在实际取舍，或首次出现新的对手威胁时，会适当延长等待。吃碰后仍重新计算弃牌；只有服务器已确认鸣牌、且新建议与先前计划一致时，才采用较短的后续节奏。等待以稳定的基础速度配合小幅、有界且偏向较短等待的随机变化，每个操作窗口只确定一次目标，不会随刷新反复抽取。节奏只影响何时提交，不改变建议选出的动作。

临近截止时会缩短等待并预留提交时间，因此不保证每次都达到目标等待时长。服务器的操作倒计时使用毫秒，计时不会因重开开关或恢复旧消息而重新获得完整时限。匹配与确认下一局采用独立的较短等待。

建议计算用完内部 2 秒预算时，自动开关保持开启，等待可用建议或下一次行动；不会使用未完成的候选结果，也不会反复重算同一个窗口。若当前窗口仍有效且收到新的完整建议，可以继续执行；若已超过提交时限，则跳过这个窗口并丢弃迟到建议，在下一个有效窗口自动继续。客户端处理这次未完成或已过期操作时不会单独关闭自动开关，真实的手动点击或按键仍会让出控制。

进入对局后，开场通知到首次发牌之间保持自动开关开启，显示“等待开局牌局信息”；完整开局信息到达后继续按建议操作。认证后 30 秒仍没有收到完整开局信息时，提示加载较慢并保持自动开启；收到可信的完整开局和新建议后继续。实际打牌期间发生漏步、无法恢复的手牌错误或解析错误仍会暂停。断线、重新认证和同步牌局期间，自动打牌开关保持开启，状态显示正在恢复，暂不提交操作。完整动作回放后需连续实时消息确认恢复边界；只有快照时继续等待完整开局信息。可信状态和新的操作窗口到达后自动继续，无需重新开关。恢复等待不会因普通的开局超时而关闭开关；若你在等待期间关闭或手动接管，恢复后也不会重新开启。回放中的旧建议、操作和倒计时不直接复用，断线前已提交但结果未知的同一步也不会再次发送。如果重新登录明确确认没有进行中的对局，则清除旧牌局恢复状态并继续自动匹配；结果未知的原匹配队列仍先取消，避免重复排队。

断线恢复由原生进程持续监督。官方客户端先自行重连；已确认断线或未知提交持续没有有效进展时，依次等待 45、90、180 秒后最多受控重载 3 次。普通页面心跳、重复的等待提示不会延长这个窗口；反复认证却未完成恢复时，每轮等待也最多 180 秒。正常等待对手操作不会触发重载。每次手动开启有独立的次数上限，恢复后正常运行不会重置次数。页面重载仍复用应用已有登录资料；需要验证码、重新登录、账号被踢下线或服务器拒绝时会说明原因并暂停，不能自动处理这些提示。

受控重载前先冻结自动操作，并在原生进程内短暂保存本次自动意图、三／四麻和东／南风选择，以及未知出牌、下一局确认、匹配队列的去重身份。只有本次重载的新页面可以一次性接收这些信息；普通刷新、重新启动应用、关闭开关或手动接管都会撤销继承。恢复后的同一步未知出牌与结算确认不重复发送；结果未知的匹配先核对原账号和官方登录状态，再取消原队列，确认取消后才能重新匹配。牌局继续时仍需完整可信状态、实时合法操作窗口和新建议。页面不回应、去重身份无法验证、重载失败或超过次数上限时停止自动恢复并说明原因，不用旧建议补发操作。

自动开启期间，应用维持后台活动，允许锁屏和显示器休眠。页面隐藏时由原生心跳继续推动 Unity 已申请的动画帧和原有自动调度，避免画面帧暂停后卡在入场或操作等待；每次只处理当前待执行帧，不补跑历史帧，已取消或已执行的回调不会重复执行。关闭自动、手动接管、页面离开或退出应用后释放后台活动并恢复原调度策略。合盖、主动系统睡眠或断网仍可能中断执行，恢复后继续遵守可信牌局与新操作窗口检查。后台活动启停、恢复阶段、有效进展、重载次数与结果会记录到文本日志；socket 关闭信息记录到结构化日志。受控重载期间继续保持原生活动，用户关闭或失败后释放。

小局结束后自动确认下一局；原生客户端已经确认时不会重复提交。整场结束后保留 45 秒供客户端播放结算，状态行显示剩余秒数；倒计时结束后刷新段位和金币、选择房间继续匹配。关闭再开启自动开关不会重新计算这 45 秒，重复的结束通知也不会延长等待。这是固定的结算等待，不是对“已返回大厅”画面的检测。排队超过 3 分钟、匹配成功后 30 秒没有进入游戏，或确认下一局后 30 秒没有收到新局消息，都会暂停并显示原因。

关闭开关立即停止后续自动操作，并取消本次自动发起的待处理匹配；已提交到服务器的牌局操作无法撤回。取消会绑定原账号和队列，迟到的匹配回执或同账号重连仍会触发取消；不会取消新账号的匹配。手动点击或按键、正常对局中客户端自行提交操作、真实牌局数据错误或可操作时建议不可用会暂停。重连恢复期间，客户端为旧操作发送的补救消息不会单独关闭开关；真实的手动点击或按键仍会让出控制。请关闭游戏内置的自动和牌、不鸣牌、摸切和拔北，避免其先提交操作导致暂停。

状态行显示等待登录、排队、计算建议、等待操作、等待确认或暂停原因；状态变化也写入本地日志。未知客户端连续等待 90 秒后暂停，不会永久显示“加载中”。当前实现已通过真实协议格式的离线三麻／四麻完整流程和请求冲突、断线、结算、取消等回归；尚未用真实账号验证当前客户端的全部画面转换和线上动作接受情况，也未检测客户端动画实际结束的时点。各类等待时长仍是初始参数，未用真人操作数据拟合，不能把离线测试当作真人节奏或实战验收。

## 实时行动建议

本人获得合法操作且信息完整时，右侧显示“当前建议”：打哪张牌、是否吃碰杠或立直、是否拔北／九种九牌流局，以及是否跳过。吃碰方案注明使用的牌和随后建议打出的牌；立直方案与同一张牌的默听分别比较。杠和拔北采用补牌后的加权估计，不提前指定未知摸牌。下方显示备选方案，比较净收益、打点、风险与牌形。服务端已提供自摸或荣和操作时优先显示可和牌提示。自动打牌关闭时，建议仅展示，由你点击游戏中的操作。

建议理由区分“当前进攻”“当前弃和”与“当前已立直”。当前弃和从预计放铳损失最小的合法牌开始，再消耗手中实际保有的防守牌，风险同时考虑所有对手；没有现物时也能选择弃和。这个防守估计放弃后续和牌，并按流局不听计算，所以不会一边显示弃和、一边靠原来的进攻收入推荐危险摸切。它是一条保守近似，没有细算防守中的偶然自摸或安全听牌收益。当前选择进攻时，未来仍可能因局面恶化而转守；“未来转守概率”和“现在已经弃和”是两件事。

每个新操作窗口都会重新比较攻守，弃和不会永久锁住后续选择。高打点或高和率只是收入的一部分，仍要覆盖当前与未来风险、他家终局付款和流局收支；没有达到固定打点或和率就一定进攻的规则。已立直后继续受摸切等合法操作限制，服务器已允许的和牌不会被防守策略跳过。

评分首先比较终局净收益和动作代价，不额外叠加牌效奖励。显示分数相同时，内部更高精度的数值仍可能不同；真正同分才依次看损失、安全牌库存、有效和牌机会与后续形状改良。字牌有役、七对子、国士或防守价值时可以保留，不能把“先打字牌”或“不摸切”当作固定规则。

每次摸牌、出牌、吃碰、杠或拔北造成手牌变化时，立即撤下旧结果并重新评估。没有当前操作窗口时显示“等待行动”的最新手牌分析，不能将它视为可立即执行的动作。点击游戏操作后也会立即撤销旧建议，直到服务端确认后再更新。缺少完整开局、漏步、未验证恢复、断线或小局结束时暂停分析。立直后普通弃牌仅允许摸切；暗杠和拔北仍以服务端允许的组合为准。吃碰后的食替禁打牌会从候选中剔除。

向听和已知牌计数按规则计算；概率、对手打点及未来牌型估值是未校准的启发式估计。两向听以上仍比接近听牌的路径粗：门清粗路径尚未确认荣和役时保守只估自摸，但后续改良仍可能形成役；未来打点也可能因实际弃宝或拆形而改变。普通四麻与三麻均可分析，未识别自定义规则、活动玩法、整场顺位积分或特殊结算。各指标的确切含义和假设见 [出牌建议](出牌建议.md)，当前攻守与同分判别的边界见 [策略说明](advisor-policy.md)。

## 本地数据与信息边界

运行数据保存在：

```text
~/Library/Application Support/Maj-Soul++/
```

`logs/` 保存每次运行的文本 `.txt` 和结构化 `.jsonl` 记录，`launcher.log` 保存启动诊断，锁文件用于避免重复启动。应用在后台写入日志，不打印终端统计。日志记录统计快照和状态，不记录登录 token；显示时间按北京时间。新的运行数据不写回应用包。

游戏页面通过系统 WebKit 原生消息接口把数据送入应用内的 Python，再更新浮层和本地日志。

开局消息可建立本小局完整基线；中途进入对局时，完整性取决于服务端恢复数据。没有可信基线时明确标注缺失；漏步、未知动作或数据不一致会取消完整标记。自动更新不能保证补回监听前的全部历史。

对手未公开手牌不会由程序推测。已知牌计数合并赤五与普通五；被鸣走的弃牌保留历史标记，但不与副露重复计数。这些计数不等于剩余牌山的精确分布。恢复快照的特殊弃牌编码及恢复边界仍待更多真实样本核对，详见 [监听与完整性分析](监听方法与完整对局信息获取分析.md)。

## 构建与维护

开发、测试和构建步骤见工程根目录的 [README](../README.md)。当前源码位于 `src/`，测试及样本位于 `tests/`，说明及规则参考位于 `docs/`。

在完成开发环境准备后运行：

```sh
./scripts/test.sh
./scripts/build.sh
```

构建产物为 `dist/Maj-Soul++.app`，不会覆盖桌面现用 App。在 Finder 中右键新构建的 App，选择“显示包内容”，可查看：

```text
Contents/
  MacOS/                  应用入口
  Frameworks/             随包 Python 运行时与二进制依赖
  Resources/
    docs/                 使用说明、方法分析和规则参考
    source/               源码工程、测试及构建配置
```

构建采用 PyInstaller 的 `onedir`、`windowed` 模式，将运行时及依赖封装为无控制台的 macOS `.app`。构建依赖记录在根目录的 `requirements-build.txt`。维护时修改源码工程，测试后重新构建；不要直接修改已签名应用内的文件。

测试涵盖协议与状态更新、初始发牌和动作去重、立直确认、整场结束重置、静默日志、原生消息桥接以及浮层布局和点击穿透。打包后还可使用 README 中的 `--verify-native` 与 `--verify-overlay` 入口验证内置运行环境。离线测试使用本地回放样本，不代表已验证所有服务端恢复情形。主动恢复回归覆盖页面心跳持续但连接停滞、正常重连、退避与上限、跨页面去重、普通刷新和用户接管竞态；这些测试不能替代真实断网及长时间锁屏验证。
